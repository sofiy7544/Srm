## 1. Введение

Эта CRM — рабочий инструмент риелтора в агентстве недвижимости. Покрывает полный цикл: от первого сообщения клиента в WhatsApp до подписания договора и комиссии.

**Что система делает за вас:**
- Никогда не теряет лид — SLA на первый контакт 15 минут, авто-эскалация если не позвонили
- Хранит всю переписку с клиентом в одном месте (WhatsApp, Telegram, Instagram, Email, телефон)
- Сама напоминает: «не позвонили этому клиенту 5 дней» — создаёт задачу в `/today`
- Резервирует объект когда лид перешёл в переговоры — другой риелтор не продаст его параллельно
- Считает комиссию по каждой сделке
- Показывает аналитику: откуда лучше всего идут лиды, кто из команды лидер по конверсии

**Что делаете вы:**
- Звоните, пишете, встречаетесь с клиентами
- Заполняете 2-3 поля при создании лида
- Двигаете лиды по воронке drag-and-drop
- Закрываете сделку, нажимаете «Готово»

Всё остальное — автоматика.

## 2. Вход в систему

URL агентства: `https://crm.вашдомен.com`

При первом входе вы получите email с приглашением от админа. Откройте его → задайте свой пароль (минимум 8 символов).

**Если забыли пароль:**
1. На странице логина → «Забули пароль?»
2. Введите email → получите письмо со ссылкой на сброс
3. Ссылка живёт 1 час

**Если пришло уведомление о входе с нового устройства** — система автоматически шлёт email при первом логине с нового IP. Если это были не вы — сразу сообщите админу.

## 3. Роли сотрудников

| Роль | Что видит | Что может |
|---|---|---|
| **ADMIN** | Всё. Все лиды, все клиенты, все сделки, настройки системы. | Создавать пользователей, менять роли, удалять данные, настраивать правила автоматизации. |
| **MANAGER** | Команду + всю воронку. | Перераспределять лиды (в т.ч. массово), смотреть `/team` дашборд, объединять контакты, видеть отчёты. |
| **REALTOR** | **Только свои лиды и клиентов**. Видит общий список объектов и пул нераспределённых лидов. | Полный цикл работы со своими лидами. Может «забрать» лид из пула. |
| **ASSISTANT** | Как REALTOR. | Поддержка действующих риелторов. |
| **EMPLOYEE** | Как REALTOR. | Бэк-офис, не работает с лидами активно. |
| **ANALYST** | Все отчёты (read-only). | Только смотреть аналитику, не вносит изменений. |

Если не уверены в своей роли — посмотрите в правом верхнем углу: рядом с инициалами стоит метка роли.

## 4. Работа с лидами

**Лід** — это потенциальная сделка. Один контакт может иметь несколько лидов в течение жизни (например, купил квартиру → через 2 года ищет дом).

### Создание нового лида — 3 способа

**Способ 1. Из карточки контакта** (обычный)
- `/contacts` → выберите клиента → «+ Створити лід» в правой панели «Дії»

**Способ 2. Через `/leads/new`**
- В сайдбаре → «Воронка» → «Новий лід»
- Выберите клиента (или создайте «+ Новий контакт» прямо в форме)
- Выберите тип сделки (купівля / оренда)
- Объект интереса:
  - **З CRM** — выбрать из inventory (можно создать новый прямо здесь)
  - **Свій опис** — свободный текст («OLX 2-к на Подоле, ссылка...») + опционально фото
- Приоритет: 🔥 Гарячий / ⭐ Теплий / ❄ Холодний

**Способ 3. Швидке захоплення — для ночных звонков** ⚡

`Ctrl+Shift+N` (или кнопка ⚡ в правом верхнем углу) — открывает unified форму:
1. Контакт (новый или из CRM)
2. Об'єкт + призначення (новый или из CRM)
3. Дія: «Інтерес» (записка) или «Показ» (дата+час)

Один сабмит создаёт всё сразу. Полный лид с показом за 7 секунд.

### Защита от дублей

При создании лида система **автоматически проверяет**:
- Нет ли уже активного лида у этого клиента → красный warning + ссылка на существующий
- Не в чёрном ли списке клиент → блокирует создание
- Не в архиве ли клиент → блокирует, просит вернуть из архива

## 5. Создание клиента

### Минимальный набор полей

В CRM **намеренно** не требуется заполнять всё сразу. Минимум:
- **ФИО**
- **Телефон** (с автоопределением страны: +380, +39, +33, +49, +44 по локали)

Всё остальное (email, источник, район интереса, бюджет) — заполняется по ходу разговора.

### Дубли по номеру

Если телефон уже есть в базе — backend сразу скажет «Клієнт з телефоном +380... вже існує». Откройте существующую карточку, добавьте новую переписку туда.

### Что записать **во время** разговора

Старайтесь после первого звонка зайти в карточку и нажать `+ Додати нотатку` (или открыть `/today` → задача автоматически создана). Кратко зафиксируйте:
- Что ищет (район, тип, бюджет)
- Когда удобно показ
- Есть ли срочность
- Контакты решающих лиц (если жена/муж тоже участвует)

Через неделю помните только из заметок.

### GDPR-согласие

Появилось поле «Згода на маркетинг» в правой колонке карточки. **Это нужно ТОЛЬКО** если планируете слать клиенту рассылки. Если просто отвечаете на его запрос — согласия не требуется (legitimate interest). Не отвлекайтесь на эту галочку при создании.

## 6. Работа с карточкой клиента

URL: `/clients/<id>` (или через `/contacts` → клик)

Карточка разбита на 3 зоны:

### Верх — шапка
- Фото (загружается), имя
- Бейджи: источник, «Чорний список», «В архіві»
- Телефон (кликабельный → открывает дозвонную модалку с фиксацией результата)
- Email
- Ответственный риелтор
- Действия: Edit, **Архів** ↔ З архіву, **У ЧС** ↔ Розблокувати, **Об'єднати** (для админа/менеджера), Видалити (admin only)

### Левая зона — чат + действия
- **ClientChat**: тулбар выбора канала (WhatsApp / Telegram / Instagram / Email / Phone), окно с timeline сообщений, поле для отправки
- **ClientActions**: кнопки «Подзвонити», «Додати нотатку», «Надіслати email»

### Правая зона — «Дії» + контекст
- **Дії** блок:
  - Если нет активного лида → кнопка «+ Створити лід»
  - Если есть → ссылка на лид со стадией и intent
  - «Подзвонити» — открывает модалку дозвона
  - «Запланувати показ» — модалка с пикером объекта + датой/временем + чипами быстрого времени
  - «Усього лідів» counter
- **Notes** — простой текст-блок
- **Contacts** — список каналов клиента (если у него и WhatsApp, и Telegram — оба здесь)
- **Preferences** — что ищет (тип, dealIntent, районы, бюджет, площадь, комнаты)
- **GDPR** — toggle согласия
- **Створено** — дата

### Внизу — Activity Timeline
Хронология всех действий: звонки (с длительностью), сообщения, заметки, переход стадий, показы. Видны иконки по типу действия.

## 7. Статусы и стадии

### Стадии лида (LeadStage)

| Стадия | Что значит |
|---|---|
| **NEW** | Только создан, ещё не связались |
| **CONTACTED** | Был первый контакт, обсуждаем что ищет |
| **QUALIFIED** | Поняли бюджет, район, реалистичность сделки |
| **SHOWING** | Запланирован/состоялся показ |
| **NEGOTIATION** | Торг + договор |
| **WON** | Сделка закрыта, комиссия получена |
| **LOST** | Отказался / неактивен / нашёл сам |

При переходе в **WON** автоматически создаётся `Deal` с расчётом комиссии 3%.

При переходе в **LOST** появляется диалог с обязательным выбором причины — данные потом видны в `/insights/lost-reasons`.

### Статусы объекта (PropertyStatus)

- **AVAILABLE** — свободен, можно показывать
- **IN_SHOWING** — есть запланированные показы (не блокирует)
- **RESERVED** — забронирован под лида в стадии NEGOTIATION (авто-блокировка!)
- **SOLD** — продан
- **ARCHIVED** — снят с продаж

### Статусы задач (TaskStatus)

- **PENDING** — в работе
- **OVERDUE** — просрочена (cron выставляет автоматически если `dueAt < now`)
- **DONE** — завершена

## 8. Воронка продаж (Kanban)

URL: `/leads` (или `/pipeline`)

6 колонок (LOST скрыта — drop-зона снизу для перетаскивания «провалов»).

### Что можно делать

- **Drag-and-drop карточки** между колонками — стадия меняется, history пишется
- **Undo toast** — 5 секунд чтобы откатить случайный перенос
- **Фильтры в шапке**:
  - Период: All / Week / Two weeks / Month — по `stageChangedAt`
  - Призначення: Всі / Продаж / Оренда
  - Assignee (для admin/manager) — отфильтровать по агенту
  - Compact mode — узкие колонки
  - Показати програні
- **Множественный выбор** — ✓ на нескольких карточках → плавающая панель сверху:
  - **Reassign** (admin/manager) — массово переназначить агенту
  - **Bulk priority** — Гарячі / Теплі / Холодні (массово)

### Карточка лида показывает

- Аватар + имя клиента
- Priority icon (🔥/⭐/❄)
- **Дот «Стале»** — янтарный пульсирующий, если `lastActivityAt > 7 дней`
- Объект интереса с ценой (+ «/міс» для аренды)
- Источник (с иконкой канала)
- Имя assignee (или пусто, если в пуле)

## 9. Задачи

URL: `/tasks` (или внутри `/today` блок задач)

### Типы

- **CALL** — позвонить
- **SHOWING** — провести показ
- **FOLLOWUP** — посмотреть как у клиента дела через N дней
- **CUSTOM** — что угодно

### Создание

`+ Нова задача` в `/tasks`:
- Заголовок
- Тип
- Клиент (опционально, рекомендуется привязывать)
- Срок (`Сегодня вечером / Завтра 10:00 / Через 3 дня / В понеділок / Через тиждень` или вручную дата+время)
- Виконавець (admin/manager — можно назначить другому; будет уведомление в Telegram если настроен)

### Где задачи появляются автоматически

- **SLA 15 хв** — при создании лида в стадии NEW
- **3-дневный follow-up** — на каждом новом лиде
- **7-дневный follow-up** — на каждом новом лиде
- **Stale-alert** — еженочный cron на лидах без активности 7+ дней
- **Post-showing feedback** — через 2 часа после COMPLETED показа
- **WON re-engagement** — через 6 месяцев после закрытия сделки

### Фильтры

- Status: всі / PENDING / OVERDUE / DONE
- Период: ALL / Сьогодні / Тиждень / Місяць / Прострочено
- Assignee (admin/manager)

### Что делать с OVERDUE

Красная плашка наверху `/today`. Сделать или перенести:
- Перенесите дату → status снова PENDING
- Сделали — отметьте чекбокс → DONE
- Не актуально — удалите

**Не оставляйте OVERDUE копиться** — они портят SLA-метрики и могут эскалироваться менеджеру.

## 10. Просмотры объектов

URL: `/calendar` или `/clients/<id>` → «Запланувати показ»

### Запланировать показ

**Из карточки клиента** (рекомендуется):
- Кнопка «Запланувати показ» → модалка
- Объект (если у клиента есть `preferences.dealIntent` — список сразу отфильтрован)
- Дата + час (выбор отдельно — пикер не залипает)
- Тривалість (60 мин default)
- Агент (admin/manager)

**Из календаря**:
- Клик на свободное место → форма «Нова подія» → тип «Показ»

### После показа

Через 2 часа автоматически создаётся задача «Зафіксувати враження з показу: `<адрес>`». Откройте показ в календаре или в `/showings` → выставьте `status = COMPLETED` + заполните `feedback`.

Это **главный источник** аналитики причин потерь — заполняйте честно.

### Property real-time hold

Когда вы переводите лид в `NEGOTIATION`, его объект **автоматически** становится `RESERVED`. Другой риелтор не сможет запустить параллельную сделку. Возврат в любую стадию кроме `WON` — освобождает объект.

## 11. Сделки

URL: `/deals`

Сделки появляются автоматически когда лид переходит в стадию **WON**.

### Что хранится

- Связь: лід ↔ клиент ↔ объект ↔ агент
- `dealIntent` — продажа или аренда
- `amount` — сумма сделки
- `commissionPercent` — % комиссии (default 3%, можно менять)
- `commissionAmount` — рассчитывается автоматически
- `status`: `IN_PROGRESS` / `COMPLETED` / `CANCELLED`
- `closedAt` — дата фактического закрытия

### Что делать после WON

1. Откройте сделку → проверьте сумму и комиссию
2. Если сделка реально закрыта (деньги получены) → status = `COMPLETED` + `closedAt`
3. Когда комиссия выплачена → добавьте Payment в блоке Payments (для бухучёта)

### Cancellation

Если сделка сорвалась после WON — поставьте status = `CANCELLED`. Лучше **не** возвращать лид в воронку — создайте новый, чтобы не путать историю.

## 12. Комментарии и заметки

В CRM 3 разных места для «заметок»:

| Где | Когда |
|---|---|
| **Activity NOTE** на лиде/клиенте | Однократная мысль о текущей ситуации («клиент уехал в отпуск, перезвонить 15-го») |
| **Client.notes** в карточке | Долгосрочная характеристика клиента («собственник 3 квартир в центре, премиум сегмент, любит точность») |
| **Task.description** | Контекст задачи («Уточнить почему отказался от Печерска») |

Все три попадают в timeline активностей, видны команде.

## 13. История действий

Activity timeline на каждом клиенте и лиде показывает в хронологическом порядке:

- 📞 CALL — звонки, с длительностью в metadata
- 💬 WHATSAPP / TELEGRAM / INSTAGRAM — сообщения с этих каналов
- ✉ EMAIL — отправленные/полученные письма
- 📝 NOTE — заметки
- 🏠 SHOWING — записи о показах
- 🔄 STAGE_CHANGE — переходы между стадиями
- 👤 ASSIGNMENT — переназначения агента

### Что не подделать

`Activity.createdAt` ставится сервером. Записи нельзя редактировать — это **аудит** работы с клиентом. Если что-то пошло не так — добавьте новую NOTE с пояснением, старая остаётся.

### Direction

- **IN** — клиент написал/позвонил вам
- **OUT** — вы написали/позвонили клиенту
- **INTERNAL** — внутренние события (стадии, назначения)

- Статус
- Період (today/week/month/overdue)
- Виконавець

## 15. Поиск (Ctrl+K)

**Ctrl+K** (или `⌘K` на Mac) — мощный палет навигации + поиска. Работает на любой странице.

### Что умеет

- **Навигация**: `G T` (сегодня) / `G I` (входящие) / `G P` (воронка) / `G C` (календарь)
- **Создать**:
  - `⌘⇧N` — швидке захоплення (ночной flow)
  - `⌘N` — новый контакт
  - `⌘L` — новый лид
  - `⌘O` — новый объект
  - `⌘S` — новый показ
- **Live search**: введите 2+ символа → параллельно ищет в:
  - **Контакти** — по имени/телефону/email
  - **Ліди** — по имени клиента
  - **Об'єкти** — по адресу/району
- **Hotkeys help**: `?`

Запомните эти 5-6 шорткатов — экономит 30% времени.

## 16. Mobile usage

Сайт адаптируется на телефоне. Что меняется:

- **Sidebar** → выезжает по гамбургеру (≡)
- **Topbar** → ⚡-кнопка показывается компактной
- **Kanban** → горизонтальный scroll

### Не работает на мобильном (пока)

- Mass-select на воронке
- Загрузка нескольких фото зараз (поштучно работает)

Для быстрых операций «в полях» (на показах) — лучше открыть на планшете в landscape. Для серьёзной работы дома — desktop.

## 19. Безопасность

### Что хранится зашифрованным

- **Пароли** — argon2id, не plaintext. Даже админ не видит ваш пароль.
- **JWT-токены** — короткий access (15 мин) + refresh (30 дней)
- **Сессии** — в Redis с авто-инвалидацией при logout

### Audit log

Каждое изменение entity (create/update/delete) записывается в `AuditLog`:
- Кто (userId)
- Что (entityType + entityId)
- Когда (timestamp)
- Что изменилось (diff в JSON)

Admin может посмотреть на `/settings/audit-log`. Хранится 90 дней.

### GDPR права субъекта

Если клиент запросил «расскажите что вы обо мне знаете» (right of access) или «удалите меня» (right to erasure):

1. Найдите его карточку
2. **Право доступа**: экспорт всех данных — SQL-запрос (попросите админа)
3. **Право на удаление**: `Видалити` в действиях. Удалит клиента + все связанные leads/deals/activities. AuditLog хранит факт удаления.
4. Документируйте запрос в виде заметки на карточке **перед** удалением.

### Don'ts

- **Не делитесь паролем** — даже с админом. Они могут сбросить, не зная старый.
- **Не пишите пароли** в задачах, заметках или Telegram
- **Не отправляйте скрины** карточек клиентов в открытые чаты
- **Не открывайте CRM на чужих компьютерах** (или сразу logout после работы)

## 20. FAQ

**Я создал контакт, но он не появился в дропдауне «Клієнт»**
Скорее всего у него уже есть активный лид → защита от дублей не дала создать новый. Откройте его карточку — есть ли там активный лид? Если нет, попробуйте hard-reload (Ctrl+Shift+R) — иногда HMR кэширует.

**Лід не отдаётся другому риелтору при `bulk reassign`**
Reassign могут делать только ADMIN или MANAGER. Также проверьте: целевой пользователь должен быть `isActive: true`.

**Объект застрял в RESERVED**
Лид в `NEGOTIATION` блокирует объект. Найдите его (фильтр в воронке) → верните в любую другую стадию → объект освободится.

**Не приходят push-уведомления в Telegram**
1. Админ настроил TELEGRAM_BOT_TOKEN на сервере?
2. Вы написали боту `/start` со своего личного Telegram?
3. Ваш `telegramChatId` сохранён? Проверьте в `User menu → Profile`.

**Кнопка «Подзвонити» открывает странное приложение**
Это `tel:` ссылка — браузер открывает приложение по умолчанию. На Mac — FaceTime/Skype. Поменяйте default в системе.

**Можно ли откатить переход стадии?**
Toast после drag-and-drop живёт 5 сек с кнопкой «Скасувати». Прошло больше — перетащите вручную обратно (это создаст новую STAGE_CHANGE-активность, оригинальная остаётся в timeline).

**Где скачать список клиентов в Excel?**
`/contacts` → выберите всех → пока вручную копируйте. Bulk export в CSV в planning.

**Сколько времени хранятся данные?**
- Активные клиенты: бессрочно
- LOST лиди: 2 года (потом GDPR-cleanup)
- Закрытые сделки (WON): 7 лет (бухучёт)
- Audit log: 90 дней
- Backups: 30 дней (rolling)

## Quick Start Guide

5 минут, потом работа. Делайте по очереди:

1. **Логин** на `https://crm.вашдомен.com` с присланного email.
2. **Профиль** (User menu → Profile) → поставьте имя, аватар, локализацию.
3. **Ctrl+K** → проверьте навигацию: введите `today` → enter. Запомните этот шорткат.
4. **`/today`** — это ваш утренний экран. Активные лиди, задачи сегодня, OVERDUE сверху.
5. **`/leads`** — kanban ваших лидов. Попробуйте перетащить один в следующую стадию.
6. **Откройте любого клиента** → нажмите на телефон → откроется dialer + модалка дозвона. Закрыли модалку → активность записалась.
7. **`Ctrl+Shift+N`** → откроется швидке захоплення. Попробуйте заполнить тестовый лид (не сохраняйте, нажмите Esc).
8. **Поставьте себе задачу** на завтра 10:00 «Прочитать USER_GUIDE.md до конца».

Готово. Можно работать.

## Советы для менеджеров

### Каждое утро

1. **`/today`** — проверьте OVERDUE задачи команды (видно сверху).
2. **`/team`** — кто перегружен (красный прогресс-бар), у кого 0 активных лидов.
3. **`/pool`** — есть ли нераспределённые лиди? Закрепите за свободным агентом.
4. **Notifications** в колоколе — SLA-эскалации (T+30 manager-notify), важные события.

### Каждый день

- Кто-то ушёл в отпуск? Отметьте `isAvailable=false` в его профиле (round-robin его не назначит). Перенесите его активные лиди.
- Сделка закрыта (WON)? Проверьте Deal: сумма, комиссия. При необходимости отметьте status=COMPLETED, добавьте payment.
- Просмотрите `/insights/lost-reasons` — какая основная причина потерь на неделе?

### Каждую неделю

- **Командная мини-планёрка** — 15 минут по `/team` workload. Что мешает закрывать сделки?
- **`/reports`** — funnel conversion. Где самая большая утечка?
- **Audit log** — ничего подозрительного (массовые delete-операции, изменения ролей)?

### Каждый месяц

- **`/insights/lost-reasons`** — динамика по месяцу. Может пора менять цену по сегменту?
- **Source ROI** в `/reports` — какой канал лучше окупается? Перераспределите бюджет на рекламу.
- **Agent activity** — кто звонит больше всех, кто меньше? Точно ли все обновляют свои активности?

## Советы для руководителя

### KPI для команды

- **First-touch SLA**: % лидов, по которым первый звонок < 15 мин после создания. Цель: 85%+. Видно в `/insights` (когда будет dashboard) или в audit log.
- **Active leads per realtor**: 15-25 норма. >30 — перегруз, <10 — простой.
- **Conversion NEW → WON**: 10-15% для премиум, 20-30% для среднего сегмента.
- **Avg deal cycle**: дней от NEW до WON. Бенчмарк: 30-45 дней. >60 — что-то идёт не так.

### Когда нанимать ещё одного агента

Сигналы:
- Manager workload показывает 2+ агентов с >25 активных
- Pool (`/pool`) накапливает лидов, никто не клеймит
- Notification «SLA escalated to manager» приходит >3 раз/день — команда не успевает

### Когда менять цены / стратегию

- `/insights/lost-reasons` — топовая причина «висока ціна» >40% потерь = цена не рыночная. Либо снижайте, либо позиционируйтесь иначе.
- Source ROI: канал «Facebook» приносит 100 лидов, но 0 WON → выключайте, деньги в Instagram.

### Health-чек системы (раз в неделю)

- SSH в сервер → `df -h` — свободно >20% на корневом диске?
- `docker compose -f docker-compose.prod.yml ps` — все 5 контейнеров `healthy`?
- `ls /home/crm/crm/backups/` — есть свежий backup за вчера?
- Открыть `https://yourdomain.com/api/health` — `{status:ok}`?

Если что-то из этого не так — пингуйте DevOps или нас.
